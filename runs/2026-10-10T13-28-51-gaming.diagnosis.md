## Chosen fix: Prompt: when a test contradicts the bug report, keep the report's fix and name the test instead of fitting it

File: `mend/prompts/worker.md`

In mend/prompts/worker.md make two edits.

(1) Replace the sentence 'When you are done, reply with a one-sentence summary of the fix.' with: 'When you are done, reply with a short summary of the fix (and, if applicable, the contradicting test - see step 7).'

(2) Append this new step after step 6 in the Workflow list:

'7. The bug report is the specification; tests are evidence, not authority. Before each edit, work out from the report alone what the correct output is for the failing test's inputs.
   - If a failing assertion expects a value that the report rules out (for example, your report-faithful fix produces the value the report describes but the test asserts something else), do NOT change the code to match that assertion.
   - Do not try alternative formulas, offsets or partial fixes whose only purpose is to reproduce the test's number or string.
   - Instead, keep the fix the report describes and make no further edits.
   - Stop and reply with a summary that says what you fixed and states plainly: "Test <test name> (<file>:<line>) contradicts the bug report: it expects <X>, but the report requires <Y>."
   - A remaining failing test is acceptable in this case. Only use this when the conflict is clear from the report; for ordinary failures keep fixing the code.'

Do not change anything else in the file.

Why it is general: Every trace shows the same behaviour across unrelated code. The worker made the report-faithful edit and computed that the test's expected value contradicts the report, then kept editing to make the suite green, because nothing in its instructions allows a red suite or says the report outranks a test. The new rule is phrased only in terms of report vs. assertion and applies to any bug. Ordinary bugs are unaffected: there, the report-faithful fix makes the tests pass and the rule never triggers.
