## Chosen fix: Prompt: don't read tests; map failing test to its source module, trust traceback over report

File: `mend/prompts/worker.md`

In mend/prompts/worker.md, replace workflow step 2 with:

"2. Do not read test files: the failure output already shows the failing test, its assertion and the expected vs actual values. Decide which library module to read from the failure, not from the report's guess. Use the traceback's source file if shown; otherwise the module the failing test file targets (tests/test_X.py -> the library's X.py). If the report names a different file than the failure points to, trust the failure. In ONE turn, request that source module and any other library modules you expect it to depend on, with multiple read_file calls. If read_file says more lines remain and the code you need is not shown yet, read the remaining range next, without re-reading anything."

Leave all other steps unchanged.

Why it is general: In every slow trace a turn went to reading a test whose assertion was already printed, or to reading the wrong or partial source serially. Telling the worker to skip test reads, follow the failure rather than the report, and batch source reads applies to any bug in any module. It saves 1-2 turns per task without changing tools or the loop. It does not repeat the reverted whole-file read_file default.

## Proposed neatlogs regression guard

`Mend: worker read a test file`: regex `(?m)^\d+\tdef test_` on the output of `read_file` spans. Flags read_file calls whose output is test code. The failure output already shows the failing assertion, so such reads usually waste a turn.
