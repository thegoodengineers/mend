## Chosen fix: Loop: seed the initial full test-suite result into the first message

File: `mend/worker.py`

In solve_task, before the while loop, run the full suite once and put its output in the first user message, alongside the file listing that is already seeded there.

1. Call `passed, output = run_tests(work)`, the plain function from mend.tasks, not the traced run_tests_tool. Wrap the call in try/except Exception; on an exception, use `output = f"(initial test run failed: {exc})"` and `passed = False`.
2. Build the first message as: `f"Bug report: {report}\n\nProject files:\n{files}\n\nInitial full test run (already done for you; do not call run_tests to start):\n{'PASSED' if passed else 'FAILED'}\n{output}"`.
3. Add one sentence after the seeded output: "Use the failing test names, assertions and tracebacks above to decide which source files to read; request all needed files in one turn."
4. Leave the rest of the loop unchanged, including auto-test after edits and finish on green.
5. Also update step 1 of mend/prompts/worker.md, keeping the rest of the prompt as is. It should now say: the initial full test run is already included in the first message, so start directly by reading the source files it points to, all in one turn. Why it is general: Every task currently begins with a turn whose only action is a full run_tests call; this is true for all three traces. Doing it in the loop removes one LLM round-trip, and its accumulated input tokens, from every run regardless of the bug or module. It also puts the traceback in front of the model before it can act on a misleading report. It extends the already-kept pattern of seeding the file listing and auto-running tests, and does not repeat any reverted change.

## Proposed neatlogs regression guard

`Mend: worker re-ran the suite to start despite seeded results`: regex `^FAILED\n` on the output of `run_tests` spans. Flags model- or auto-initiated full test runs that still fail. After this fix the initial failing output is seeded without a run_tests span. A FAILED run_tests span now means either the worker ignored the seeded results and re-ran the suite, or an edit did not fix the bug. Both mean wasted turns worth inspecting.
