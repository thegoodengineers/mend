## Chosen fix: Loop: after a still-failing post-edit run, inject a report-vs-test contradiction check

File: `mend/worker.py`

In solve_task, keep the auto-run and finish-on-green behaviour unchanged. Add a module-level constant CONTRADICTION_NOTE with this text: "The suite still fails after your edit. Before editing again, work out by hand what the bug report says the failing call should return and compare it with the test's expected value. If your current code already produces what the report describes and the test expects something the report rules out, the test contradicts the report: do NOT change the code to match that test, and do not invent a new interpretation just to make it pass. Stop now and reply with a short summary that states the fix you made and names the contradicting test (file and test name) and why it conflicts with the report. Only if the report itself is not yet satisfied should you continue fixing." In the loop, after computing tool_results for a turn, check two conditions: edited_this_turn is True, and the full-suite result for this turn failed. The result failed if the automatic run (auto) does not start with 'PASSED', or if the model's own full run_tests call (no pattern) does not start with 'PASSED'. When both hold, append {"type": "text", "text": CONTRADICTION_NOTE} to tool_results before appending the user message. Do not add this text to the system prompt and do not inject it on any other turn. Leave the existing end_turn path as is, so the worker's text reply becomes result['summary'].

Why it is general: The note fires only in one situation: an edit was made and the full suite still fails. For ordinary bugs this is rare, so the token cost is small, unlike the reverted always-on prompt rule. It never names a module or bug. It asks the worker to check its code against the report independently of the test, which is right for any task. When the remaining failure is a genuine unfixed part of the report, the worker keeps fixing as before. When the test contradicts the report, it stops and names the test instead of bending the code. This is a different mechanism from the reverted prompt change: a conditional loop nudge at the moment the bending happens.

## Proposed neatlogs regression guard

`Mend: passed after fitting code to a test it doubted`: regex `(?is)suite_passed.*\b(the test expects|to (match|satisfy|fit) the test|test (is|may be) (wrong|incorrect)|typo|doesn't make sense)\b` on the output of `solve_task` spans. Flags runs that auto-finished on a green suite while the worker's final reasoning shows it was conforming to a test expectation it questioned. This is the visible symptom of bending code to a test that contradicts the bug report.
