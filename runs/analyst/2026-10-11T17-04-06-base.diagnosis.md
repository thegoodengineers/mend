## Chosen fix: Inject database schema into the system prompt so the analyst can query immediately

File: `agents/analyst/agent.py`

1. In agents/analyst/agent.py add an undecorated helper `_schema_overview() -> str`. It opens `_db()` and reads every table name from sqlite_master (type='table', ORDER BY name). For each table it runs `PRAGMA table_info(<table>)` and `SELECT * FROM <table> LIMIT 3`. It returns lines formatted as 'table <name>: col1 TYPE, col2 TYPE, ...', followed by 'sample: ' and the three rows. Do not route it through the decorated `list_tables`/`describe` functions, so no tool spans are emitted.
2. In `answer_question`, after `system = PROMPT_FILE.read_text(...)`, append the following to `system`: '\n\nDatabase schema (complete; you do not need list_tables or describe unless a query fails on a column):\n' + _schema_overview() + '\n\nWrite the SQL query directly in your first turn. Avoid SQL reserved words as aliases. When you have the value, call the finish tool (a real tool call, not text) with just the value.'
3. Compute the overview once at module level (or cache it with functools.lru_cache), because the database is read-only.
4. Keep the list_tables and describe tools available as fallbacks.

Why it is general: Every question begins with the same schema discovery, costing two model turns and their tokens on every run whatever is asked. Supplying the schema up front removes that cost for any question on any SQLite database, since it is generated from the database itself. The prompt additions are generic SQL hygiene and tool-use rules, not tied to any particular question.
