# hwkit: the rest of the board, around hwlib

[`hardware/hwlib`](../hardware/README.md) is the benchmark sandbox for the hardware transfer test. Its
designs and testbenches are sha256-pinned ([`evidence/scorer-pin.json`](../evidence/scorer-pin.json)),
and the worker sees its full file list. So nothing in `hardware/` changes; new hardware lives here.

hwkit adds the blocks a real board needs around hwlib, in the same style: Amaranth HDL
(`amaranth==0.5.4`), one `sync` clock domain, ports in each docstring, and each design checked cycle by
cycle against a plain-Python model.

| Design | What it is | Checked by |
|---|---|---|
| [`UartRx`](hwkit/uart_rx.py) | 8N1 receiver, the partner of hwlib's `UartTx`. Two-flop synchroniser, samples mid-bit, rejects glitches, flags framing errors and recovers after a break. Latency is documented and tested. | every byte class at 5 divisors; back-to-back frames; ±3% baud mismatch; glitch; break then recovery; loopback with hwlib `UartTx` |
| [`SpiMaster`](hwkit/spi.py) | Mode 0 (CPOL=0, CPHA=0), 8-bit, MSB first, full duplex, configurable clock divider | a Python mode-0 slave model, non-palindromic bytes, 8 clocks per frame, start-while-busy ignored |
| [`LFSR`](hwkit/lfsr.py) | Fibonacci LFSR with maximal-length taps for 3–20, 24, 31 and 32 bits (XAPP052), or custom taps | taps proven maximal for every width up to 20 by the Python model; hardware equals the model; full period; enable |
| [`EdgeDetect`](hwkit/sync.py) | Synchroniser plus one-cycle rise/fall pulses | latency, one pulse per edge, nothing on steady input |
| [`SevenSeg`](hwkit/sevenseg.py) | Hex digit to 7 segments, blanking, common-anode option | all 16 glyphs against a hand-written segment table |
| [`UartEcho`](hwkit/echo.py) | Composition: hwkit `UartRx` → hwlib `SyncFIFO` → hwlib `UartTx` | bytes come back in order; a 20-byte burst through a 2-entry FIFO loses nothing |

```bash
pip install -e ".[dev,verilog]"
pytest -q hwkit                       # 79 testbenches, including the Verilog up-to-date check
python scripts/hwkit_mutants.py       # 19 planted mistakes; every one must make a testbench fail
python scripts/hw_demo.py list        # all 15 designs, hwlib and hwkit
python scripts/hw_demo.py verilog all # regenerate hwkit/verilog/*.v
python scripts/hw_demo.py stats       # flip-flops and logic per design -> RESOURCES.md
```

**Are the testbenches any good?** `scripts/hwkit_mutants.py` plants 19 single, plausible mistakes
(off-by-one bit counts, reversed bit order, wrong clock phase, no synchroniser, a FIFO read while the
transmitter is busy, and so on) and checks that each one fails a test. Writing it found two real gaps
in the first draft of the tests: every SPI test byte was a bit-palindrome, so a reversed bit order went
unnoticed, and nothing pinned the receiver's latency, so removing the synchroniser went unnoticed. Both
are now covered: 19 of 19 caught.

**Verilog.** `hwkit/verilog/` holds every design, hwlib's included, generated by the pinned
`amaranth-yosys`. A test regenerates each one and compares it byte for byte, and checks that the three
files in `hardware/verilog/` still match their generator. **Resources:** see [RESOURCES.md](RESOURCES.md).
